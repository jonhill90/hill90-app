## Decisions I made without you — all reversible

1. **The app keeps its own Postgres, Keycloak and MinIO** rather than consuming
   Hill90's. Evidence: Hill90's Postgres has one role (`hill90`, different
   password) and a health check that *asserts* platform-only databases; Hill90's
   Keycloak serves realm `platform` only (`hill90` is a live 404) and its clients
   are `grafana`, `portainer`, `hill90-vault` — all infra SSO. **Caveat I want to
   flag: the Keycloak half of this is weaker than the Postgres half.** Adding an
   app realm to Hill90's Keycloak is one bind-mount line. If you want one
   Keycloak, that decision is cheap to reverse.

2. **Naming scheme: Hill90's convention plus an `app-` tenant component.**
   `container_name: ${CONTAINER_PREFIX:-}app-<name>`; service keys get `app-` only
   where they collide (`app-postgres`, `app-keycloak`, `app-minio`,
   `app-postgres-exporter`); Traefik router names all `app-*`; the app's Keycloak
   hostname is `${APP_AUTH_HOST:-app-auth}`. Verified zero overlap against the
   live VPS's 13 containers. Alternatives I rejected, and why, are in the decision
   record — the main one is uniform `app-` on every service key, which is more
   future-proof but rewrites ~20 internal URLs.

3. **`postgres-exporter` is kept, not deleted.** I had earlier concluded it should
   be deleted as an infra duplicate. That was wrong and I reversed it: Hill90's
   exporter monitors Hill90's database and cannot scrape the app's, so deleting it
   would have silently ended monitoring of the app's Postgres.

4. **Override layer targets the prod files, not a fork.** `deploy/compose/overrides/`
   mirrors Hill90's structure.

## Open questions for you

- **Project naming vs Traefik's constraint.** The override stacks must run under a
  project name Traefik allows. I used `hill90-local`, which works, but sharing one
  project across per-stack `up` invocations makes Compose reconcile against only
  the files passed (it left `ai` and `knowledge` in `Created` until re-upped).
  Per-stack projects are cleaner but each name must be added to Hill90's
  constraint, because Traefik v2.11 cannot do `LabelRegexp`.
- **`NETWORK_PREFIX` is now live in the production compose files.** A shell value
  takes precedence over `--env-file`, and both repos share a deploy user on the
  VPS where Hill90's tooling sets that variable. Risk flagged, not proven —
  confirming it needs VPS inspection.

  on this branch and is unrelated; it also landed on main as **#9**. I did not

## Bugs found that were nobody's plan

Each of these presented as something other than what it was:

| Symptom | Actually |
|---|---|
| Keycloak: `password authentication failed for user "hill90"` | two containers aliased `postgres` on the shared network; it reached Hill90's |
| every app hostname 404 | Hill90's Traefik constraint omitted the app's project, while its own comment claimed it was covered |
| `--infra` preflight fails naming three networks | `.env.local` kept `hill90local` after Hill90 renamed to `hill90dev`; the fix reached fresh clones and no existing working directory |
| `provision-akm-db.sh` "fails silently" | `scripts/_common.sh` does not exist in this repo at all; both provision scripts die at line 7, loudly. The missing `docker exec -i` is real but secondary |
| api mount denied locally | prod hardcodes `/opt/hill90/agentbox-configs`, a VPS-only path, as both a mount and an env var passed to every agent |
| `ai`/`knowledge` crash-loop | `/etc/akm` is populated by a deploy step that stayed in Hill90 |

Two of my own claims were false and are corrected in the record: `README.md`
asserted a "Verified cold" 200 for `auth.localtest.me/realms/hill90` that was only
ever obtainable while the app was hijacking Hill90's hostname; and I described the
`postgres` collision as removed when it is only masked by Docker resolver
ordering. An adversarial subagent audit found both.

**One thing I got wrong twice in the same way:** I twice reported a 404 as a bug
when the router rule simply did not cover the path I probed. `api.localtest.me/`
404s because the API defines no route at `/`; the UI 404s at `app.` when
production routes it at the apex. Traefik's own 404 is `text/plain "404 page not
found"`; an app 404 carries the app's headers (`X-Powered-By: Express`). Check the
router rule before trusting a probe — mine included.
